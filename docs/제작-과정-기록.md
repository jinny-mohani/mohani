# 함께 가요! 제작 과정 기록

Nov 15, 2026 · @허지니

## 개요

친구와 공유하는 여행 앱 '함께 가요!'를 기획부터 피그마 프로토타입까지 Claude 채팅 한 곳에서 만들었어요. 이 문서는 그 과정과, 다음 단계(Claude Code로 실제 앱 만들기)에서 챙길 점을 정리한 기록이에요.

- **앱:** 2박 3일 여행 정보를 친구들과 함께 쓰고 고치는 모바일 웹앱(PWA). 로그인 없이 초대 링크로 들어오고, 데이터는 구글 시트에 저장해요.
- **결과물:** [기획안](https://claude.ai/artifact/8sk3WHagQnBYxhaZ3Vsbhp), 피그마 와이어프레임 42개 화면 + 프로토타입 연결, 컬러 시안 2종(보류)
- **역할:** 지니님은 방향과 피드백, Claude는 문서 작성·피그마 제작·점검

## 진행 과정

기획을 먼저 확정하고 화면을 만든 뒤, 피드백과 점검을 여러 번 반복했어요.

1. **도구 선택:** 구조·화면 설계는 Claude 채팅(Cowork), 실제 앱 제작은 Claude Code로 나누기로 함
2. **기획안 작성:** 앱 이름·제작 이유·핵심 기능(예약정보, 준비물, 일정, 장소, 친구들)을 Claude Docs로 정리
3. **기획 다듬기:** 항목별 결정 사항을 하나씩 질문·답변으로 확정 (모두 편집 가능, 삭제 보관, 재접속, 동시 편집 등)
4. **피그마 와이어프레임:** 색·글꼴 규칙을 정하고 컴포넌트 → 주요 화면 → 세부 화면 순서로 제작
5. **피드백 반복:** 피그마를 직접 보고 목록으로 피드백 → 한 번에 반영 (10회 이상)
6. **디자인 크리틱:** design-critique로 전체 흐름 점검 3회, 우선순위별 반영
7. **프로토타입:** 혼자 하는 사용성 테스트용으로 핵심 과제 5개를 링크로 연결 + 체크 표
8. **문구 다듬기:** ux-copy로 용어·단위 통일, 디자이너 메모 제거
9. **컬러 시안:** 톤 2종을 입혀 봤지만 보류. 참고 앱 스크린샷을 기준으로 다시 하기로 함

## 주요 결정 사항

초기 버전은 '단순하게, 친구 4명이 쓰기에 충분하게'를 기준으로 정했어요.

| 영역 | 결정 |
| --- | --- |
| 입장 | 로그인·초대 코드 없이 초대 링크만. 처음 들어올 때 프로필을 고르고, 브라우저가 기억 |
| 편집 | 모든 멤버가 자유롭게 쓰기·수정·삭제. 삭제는 시트에 '삭제됨' 표시하고 최근 삭제에서 되살리기 |
| 동시 편집 | 같은 항목을 동시에 저장하면 팝업으로 어느 글을 남길지 선택 |
| 저장 | 구글 시트 + Apps Script, 사진은 구글 드라이브 |
| 오프라인 | 보기만 가능 |
| 삭제 방식 | 항목 누르기 → 수정 화면 → 작은 삭제 버튼 (밀어서 삭제 없음) |
| 홈 | 03 하나만. 여행 중 날짜별 홈(04)은 다음 버전 |
| 장소 주소 | 구글 지도 링크를 넣으면 주소 자동 입력 |
| 화면 규칙 | 360px, 그레이만, 본문 16px, 버튼·입력 52px, 선택 = 검정 바탕 + 흰 글씨, 닫기 ×는 오른쪽 |
| 빼두기 | 알림, 정산, 앱스토어 출시, 충돌 팝업에서 상대 글 보기 |

## 체크해야 할 사항

Claude Code로 넘어가기 전에 확인할 것들이에요.

- [ ] 피그마 프로토타입을 화면별로 눌러 보며 흐름 점검 (지니님)
- [ ] 혼자 사용성 테스트 5개 과제 수행 후 막힌 곳 메모
- [ ] 기획안이 피그마 최신 상태와 같은지 (Claude Code가 기획안을 설계도로 씀)
- [ ] 모든 버튼·카드에 프로토타입 링크가 걸려 있는지
- [ ] 용어 통일: 예약은 '건', 준비물·체크리스트는 '개', 브레이크타임, 날짜 뒤 '까지'
- [ ] 화면에 디자이너용 메모 문구가 남아 있지 않은지
- [ ] 터치 영역 44px 이상 (작은 아이콘은 hit-area 추가)
- [ ] 컬러 방향: 참고 앱 스크린샷 준비 (색은 디자인 토큰으로 나중에 교체 가능)
- [ ] 개발 전 accessibility-review로 대비 점검
- [ ] 계정 준비: 구글 계정(시트·Apps Script 배포), 무료 호스팅(GitHub Pages 또는 Vercel)

## 주의할 사항

작업 중에 실제로 겪은 문제와 해결 방법이에요.

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 캐릭터 배경이 흰색으로 나옴 | 업로드 용량을 줄이려고 PNG를 JPG로 바꾼 | 투명 PNG 유지. 이미지는 형식을 바꾸지 않기 |
| 피그마 이미지 업로드 도구가 막힘 | 보안 프록시가 업로드를 차단 | 이미지를 코드로 직접 넣음 (토큰 많이 사용). 가능하면 직접 피그마에 끌어다 놓기 |
| 입력창 높이가 본 컴포넌트를 따라가지 않음 | 인스턴스에 고정 높이가 남아 있었음 | 인스턴스는 Hug, 높이는 패딩으로 제어 |
| 하단 버튼·글자가 잘림 | 고정 너비·높이 프레임 | 텍스트는 내용에 맞추기, 화면 높이는 내용에 맞게 다시 계산 |
| 화면에 디자이너 메모가 노출됨 | 설명을 UI 문구처럼 넣음 | 메모는 레이어 이름이나 화면 밖 주석으로 |
| 닫기 ×가 왼쪽에 있었음 | 저장이 오른쪽 위에 있는 패턴을 그대로 가져옴 | 패턴은 화면 구조에 맞는지 확인하고 쓰기 |
| 컬러 시안이 촌스러움 | 회색 전체에 색을 섞고 포인트색을 여러 곳에 뿌림 | 배경·글자는 무채색, 포인트색은 하나만 절제해서. 참고 앱 스크린샷을 먼저 준비 |
| 실패한 스크립트가 전부 취소됨 | 피그마 작업은 한 번에 전부 성공하거나 전부 취소됨 | 큰 작업은 단계를 나눠서 실행 |

기획상 한계도 있어요. 로그인이 없어서 링크를 아는 사람은 누구나 수정할 수 있고, 아이폰 사파리는 홈 화면에 추가하지 않으면 저장된 여행 정보를 지울 수 있어요.

## 토큰 아끼는 법

토큰을 가장 많이 쓰는 건 스크린샷, 이미지 데이터, 긴 문서를 통째로 읽고 쓰는 일이에요.

1. **피드백은 모아서 한 번에:** 화면 번호별로 목록을 만들어 보내면 작업 한 번에 여러 개를 반영해요.
2. **화면 번호로 말하기:** "07-2 하단 버튼"처럼 짚으면 Claude가 찾는 데 토큰을 덜 써요.
3. **스크린샷은 필요할 때만:** Claude에게 "확인용 스크린샷은 작게, 꼭 필요할 때만"이라고 요청해요.
4. **이미지는 직접 피그마에:** 캐릭터·사진은 직접 끌어다 놓고 위치만 알려 주면 가장 저렴해요.
5. **색·스타일은 레퍼런스로:** 말로 설명하며 여러 번 고치는 것보다 참고 앱 스크린샷 한 장이 훨씬 적게 들어요.
6. **시안은 작게 먼저:** 크게 바꾸는 작업은 화면 2\~3개에만 먼저 적용하고, 정하면 전체에 반영해요.
7. **대화가 길어지면 새로 시작:** 이 문서와 기획안 링크를 첫 메시지에 넣으면 맥락을 이어갈 수 있어요.
8. **스킬은 단계별로 하나씩:** 필요할 때만 부르면 지침을 읽는 비용이 줄어요.

## 다음 단계

피그마 점검이 끝나면 기획안을 최신으로 맞추고 Claude Code로 넘어가요.

1. 피그마 화면별 점검 → 피드백 목록 전달 (지니님)
2. 피드백 반영 + 기획안 최신화 (Claude)
3. Claude Code 준비: Claude 계정으로 로그인(디자인 플러그인 연동), frontend-design 스킬 설치, Figma MCP 연결
4. 구글 시트 템플릿 + Apps Script
5. PWA 뼈대 → 화면 구현(홈 → 예약 → 준비물·체크리스트 → 일정 → 장소 → 친구들) → 기능 연결
6. 폰에서 홈 화면에 추가해 직접 사용

Claude Code에서 새 대화를 시작할 때는 이 문서, [기획안](https://claude.ai/artifact/8sk3WHagQnBYxhaZ3Vsbhp), 피그마 링크를 함께 주면 돼요.
